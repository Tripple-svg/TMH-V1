# Haven launch handoff

Branch: `feat/haven-playbook-optimization`, based on `9694094`. Changes are in the working tree. No commit, push, deployment or production migration was performed.

## Visitor behavior

- The free Brand Review is the main offer. Keep the approved homepage headlines, paragraph, layout, media and preloader. Haven explains what it can see, what the score means and one practical next step. It can talk with owners who do not have a website or profile yet.
- A wrong website or screenshot can be corrected on the scorecard before choosing Continue to Chat. The owner can then return to the same conversation and see any saved score. There is no post-start Review Source link, Edit Review Details or Restart Review. Support handles personal corrections. The server locks the source, and the database blocks stale corrections and rescoring. The migration also locks existing reviews with saved user turns.
- Need Help on the homepage can help with marketing and website navigation. Support's Ask Haven opens one dedicated, resumable conversation with the same welcome bubble styling. It handles saved review access, purchase recovery, existing bookings and site problems. The human form remains available. The intentional new-chat button still works.
- Haven should sound natural, ask only for the material missing detail, and never diagnose from the score alone. For a seller whose customers go quiet after hearing the price, first find out what reason they hear to choose the offer. For a website request, find out what it must let the customer do before suggesting a project. For a content calendar, clarify what the audience should understand or do if it is not clear.
- Give a useful suggestion if that is enough. Recommend the Playbook when the owner wants to work through a gap in their foundations that it covers, or invite them to the free strategy call if there is a concrete need for the team to scope. Check existing bookings. Keep general chat, the brand review and support transcripts separate. Use limited verified audit context only when asked for or agreed to in the relevant chat.
- A Playbook preview or grounded recommendation asks permission and offers Yes and No. A matching Yes opens the public Playbook section without opening checkout or unlocking the ebook. A direct purchase request gives the checkout panel action; the download stays behind verified payment or verified recovery. Data access, footer, Support and other navigation buttons take visitors to the relevant destination.
